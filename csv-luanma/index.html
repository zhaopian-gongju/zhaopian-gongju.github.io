哪些 CSV 容易乱码

从电商后台、问卷平台、各种管理系统导出的 CSV，或者别人用 Mac 发过来的 CSV，在简体中文 Windows 上用 Excel 双击打开时，经常是中文全变成乱字。数据本身没坏，只是 Excel 认错了编码。

为什么会乱码

CSV 是纯文字文件，里面的中文可以用不同的“编码”存，常见的有 UTF-8 和 GBK。很多网站、系统导出的 CSV 是 UTF-8，而在简体中文的电脑上用 Excel 双击打开时，如果文件开头没有一个叫 BOM 的标记，Excel 会按 GBK 去读，“中文”两个字就变成了“涓枃”这类乱码。这里做的事就是：认出原来的编码，再存成开头带 BOM 的 UTF-8，Excel 一看就知道该怎么读。

常见问题

不想用网页，Excel 里自己怎么弄？
新版 Excel：新建空白表格 → “数据” → “从文本/CSV” → 选文件 → “文件原始格式”选“65001: Unicode (UTF-8)” → 加载。或者用记事本打开 CSV，“另存为”时编码选“带有 BOM 的 UTF-8”。

自动判断的编码不对怎么办？
第②步预览里如果还是乱码，点别的编码按钮，直到预览里的中文正常，再生成。简体中文的老文件一般是 GBK；繁体（台湾、香港）的老文件可能是 Big5。

身份证号、订单号打开后变成 1.23E+17、最后几位变成 0？
这不是乱码，是 Excel 把长数字当成了数字。本页不改内容，解决不了这个；可以在 Excel 里用“数据 → 从文本/CSV”导入，把那一列设成“文本”。

WPS 打开也乱码能用吗？
能，转换后的文件 WPS 一般也能直接认出来。

几百 MB 的大文件能转吗？
识别和转换都在你的设备上完成，靠本机内存。文件特别大时手机可能不够用，换电脑更稳。
